# 字节级真实文本实验结果

实验日期为 2026 年 10 月 23 日。两份真实英文文本均通过编码、三种解码和原文字节还原，六份落盘还原文件的 SHA-256 与相应原文完全一致。本轮有 360 条正式计时记录；加上预热，共进行了 396 次完整输出比较。

原始记录位于 [`results/2026-10-23-byte-text`](../results/2026-10-23-byte-text/)。所有数值均来自实际运行；表内数字为便于阅读而四舍五入，CSV 保留原始精度。

## 环境与数据

- CPU：Intel Core i9-12900H，20 个逻辑处理器。
- 系统：Windows，build 26200；电源计划为均衡模式。
- 编译：MSVC 19.44.35229，C++17，x64 Release，生成工程使用 MaxSpeed 优化。
- 方法：每种情况预热 3 次、测量 30 次，按轮轮换执行顺序。以中位数比较；未固定 CPU 核心、频率或后台负载。
- 代码：基于 `22eaa739c59b7f0c6c8adcf949d6f695ff806e45` 加本地测试程序改动。测试时每个 C++ 源文件和头文件、CMakeLists 及可执行文件的 SHA-256 已保存于 metadata.json，供之后提交时核对。

## 目前可以得出的结论

当前批量缓冲版本在这台电脑和两份文本上均比当前基线快，纯解码加速比约为 1.51；加入原文字节还原后约为 1.49。它包含 Base 合并，并减少了 64 位窗口重复装载。这是本项目当前实现之间的比较，不是与原论文实现的直接比较。

单独 Base 合并的中位数收益较小，不同版本的四分位区间存在重叠。本轮不足以证明它具有稳定且可推广的独立收益，应保留原始数值，不把它写成明确的大幅改进。

标准正确性检查共 4 项，全部通过：原解码检查、编码器联调、统计函数检查和文件测试程序检查。文件程序检查还验证了三份输出的哈希，以及旧结果目录不会被覆盖。测试日志另存于原始记录目录。
