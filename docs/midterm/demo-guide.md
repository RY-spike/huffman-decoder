# 中期备用演示操作说明

5分钟PPT自述优先，程序用于准备、追问或获准的现场展示，不额外增加演示时间。

## 答辩前准备一次

在仓库根目录、Visual Studio 2022 Developer PowerShell中执行：

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
# 仅首次下载需要联网；已有语料时会核对固定哈希
.\scripts\fetch_corpus.ps1
.\scripts\run_midterm_demo.ps1
```

依赖沿用Git、PowerShell、Visual Studio 2022的C++工作负载和内置CMake，无需新插件。移动仓库后重新配置构建，不复制旧CMake缓存作为新位置的构建结果。

## 已准备好后运行这一条

在克隆仓库根目录打开PowerShell：

```powershell
.\scripts\run_midterm_demo.ps1
```

脚本不联网、不下载、不编译，依次完成：

1. ABCA手算样例：检查编码为0x58、有效6位、输出4个符号，三个解码版本均还原ABCA。
2. 4项CTest：失败或无测试注册时报错。
3. 两份全文：预热1次、测量3次，比较完整输出，并核对6份还原文件哈希。
4. 保存日志和版本收据，全部通过后打印`MIDTERM DEMO PASS`。

默认输出到新的`build/midterm-demo-时间戳`；也可传`-OutputDirectory results/自定义新目录`归档。目录必须尚不存在，防止覆盖。10月25日实际准备记录在`results/2026-10-25-midterm-demo/`。

演示有36条正式计时（2×3×2×3），含预热共48次解码结果比较。它只验证可运行性；汇报速度使用10月23日360条正式测量，不挑选现场最快的一次。

## 如何讲解

- 小样例可以手算，最后两位补零不属于原文。
- 四项CTest各包含相应检查，并非只测试四个输入。
- 真实文件经过完整输出比较与落盘哈希核对，不能只比较文件大小。
- 纯解码与字节还原计时边界不同，两者都排除磁盘读写。

## 异常处理与离线备用

| 情况 | 处理 |
| --- | --- |
| 缺exe或源码晚于exe | 答辩前重建Release；现场展示已保存记录。 |
| 缺语料或哈希不同 | 准备sources.json对应文件，不修改哈希掩盖差异。 |
| 输出目录已存在 | 换新目录或使用自动命名。 |
| 测试、还原比较失败 | 保存失败日志，定位原因，不能宣称此次通过。 |
| 设备策略限制脚本 | 使用设备允许的执行方式，不临时更改全局策略。 |

同目录`demo-backup.html`来自实际日志和正式CSV，是离线静态记录，不表示程序实时运行。可提前打开或截取放入PPT备用页。

答辩前在同一演示电脑跑通一次，确认文本、程序和记录本地可读；保存最终提交号。程序通过不能代替个人理解、组员独立复核或导师审核。
